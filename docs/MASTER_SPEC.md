# Master Product Specification

更新日: 2026-08-22  
版: v0.2  
状態: 現在仕様の統合版

## 1. 製品定義

本製品は、日本株の売買を自動実行するボットではない。

毎営業日11:30時点で利用可能な情報を使い、現在の保有株・現金・口座区分・税金・取引コスト・新規候補を同時評価し、12:30に向けた投資提案を作る意思決定支援システムである。

最終判断と実注文はユーザーが行う。

## 2. 中心目標

中心目標は「おすすめ銘柄を順位付けすること」ではない。

> 毎営業日11:30に、12:30以降に保有すべき目標ポートフォリオを計算し、現在の保有から何株を増やす・維持する・減らす・売るべきか提案する。

現在のポートフォリオをそのまま維持する反実仮想と、売却・買い増し・新規購入・現金化を組み合わせた代替ポートフォリオを比較する。

## 3. AIがすること・しないこと

### すること

- 市場・財務・前場データを取得する
- 各銘柄の将来リターン、下振れ、不確実性を予測する
- 現在保有株と新規候補を同時評価する
- 取引コストと推定税影響を見積もる
- 目標保有株数を計算する
- BUY / HOLD / REDUCE / SELL / SKIP を提案する
- 11:30提案が完成したことをスマホへ通知する
- ユーザーが入力した実際の約定を翌日の状態へ反映する

### しないこと

- 実注文を送信する
- 証券会社で注文を取消・変更する
- 利益を保証する
- 税務申告額を確定する
- LLMの自由文章だけで売買判断を決める
- 未来情報を使って過去成績をよく見せる

## 4. 1日の基本フロー

```text
前日まで
日次・財務・市場データを更新
全対象銘柄を広く評価
新規候補を抽出

当日08:50まで
現在保有株を必ず加える
前場監視対象を確定

09:00〜11:30
保有株と新規候補の前場情報を取得

11:30
Alpha入力を凍結
保有株・候補・現金を同時再評価

11:30〜11:40
予測更新
取引コスト推定
税影響推定
Daily Portfolio Decision Engine
100株単位への最適化

11:40頃
スマホに提案完成を通知

12:30まで
ユーザーが提案を確認し、必要なら自分で注文

取引後
実際の約定株数・価格を入力または取り込む
翌日の保有状態へ反映
```

時刻は初期案であり、データ提供条件と実運用テストで調整可能にする。

## 5. 判断対象

11:30のDecision Universeには最低限次を含める。

- 現在保有しているすべての銘柄
- 口座ごとの保有ロット
- 利用可能現金
- 新規候補
- 未反映の約定・調整対象
- 現金という有効な配分先

広い株式ユニバースから日次モデルで候補を絞ってよいが、現在保有株を順位が低いという理由で評価対象から外してはならない。

## 6. 最終アクション

| Action | 定義 |
|---|---|
| BUY | 推奨株数が現在株数を上回る。新規購入と買い増しを含む |
| HOLD | 推奨株数がノートレード帯の中にあり、現在株数を維持する |
| REDUCE | 推奨株数が現在より少ないが0ではない |
| SELL | 保有中で推奨株数が0 |
| SKIP | 未保有候補で推奨株数が0 |

機械学習モデルはこの5分類を直接売買命令として出さない。予測値をDecision Engineへ渡し、現在株数と推奨株数の差からActionを生成する。

## 7. 表示の中心

内部では円・比率・期待リターン・リスクで最適化してよい。

ユーザー画面では株数を中心にする。

```text
A社 / 特定口座
現在 300株
推奨 400株
BUY 100株
必要資金 約xxx円
```

```text
B社 / NISA
現在 500株
推奨 300株
REDUCE 200株
受取見込 約xxx円
推定税影響 0円
```

各提案には次を表示する。

- 銘柄名・コード
- 口座区分
- 現在株数
- 推奨株数
- 増減株数
- Action
- 現在のままHOLDした場合の期待値
- 提案後の期待値
- 推定売買コスト
- 推定税影響
- 純改善期待値
- 下振れリスク
- 予測不確実性
- 短い判断理由
- データ時点・モデル版

## 8. 保有・口座管理

保有は `symbol × account_bucket` で管理する。

同一銘柄をNISAと特定口座で同時に持つ場合も別ロットとして扱う。

最低限管理する項目:

- 銘柄
- 口座区分
- 源泉徴収方式などの口座設定
- 保有株数
- 平均取得単価
- 現在価格
- 時価
- 含み益・含み損
- 年内確定損益
- ユーザーが入力した繰越損失
- NISA簿価
- ユーザーが入力したNISA枠情報
- 利用可能現金
- 注文・約定反映待ち金額

税計算は推定値であり、税務申告の確定計算ではない。

## 9. 予測モデルの役割

予測モデルは各銘柄について次を推定する。

- 1営業日期待超過リターン
- 5営業日期待超過リターン
- 20営業日期待超過リターン
- 下振れ分位点
- 大幅下落確率
- 前場情報による予測修正
- 予測不確実性
- 流動性
- スプレッド・スリッページ・価格影響に必要な情報

モデルは何株買うかを直接決めない。

特徴量候補の詳細な正本は `docs/FEATURE_CATALOG.md` とする。

方針:

- MACD、RSI、移動平均、Bollinger、ADX、ATR、出来高、財務、相対強度、需給、市場環境、前場指標を広い候補プールとして持つ
- 一般的に有名という理由だけでChampionへ採用しない
- FeatureSet V0 / V1 Core / V2 Extended / V3 Data-dependentの順で段階的に追加する
- 特徴量群AblationとOut-of-Sample検証で、本当にDecision Engineを改善するものだけ残す
- RSIやMACD等を固定のBUY / SELLルールへ変換しない
- 特徴量定義、パラメータ、計算実装、ライブラリ版、warm-up、Point-in-time規則をバージョン管理する

## 11. 取引コスト

SBI証券の手数料無料条件を使う場合でも、手数料0だけで判断しない。

最低限次を含める。

- 売買手数料
- Bid-Ask spread
- Slippage
- 流動性によるMarket Impact

手数料は設定値とし、無料条件をソースコードへ固定しない。

## 12. 税影響

税計算は独立したTax Engineにする。

考慮対象:

- NISA / 特定口座 / その他の対応口座
- 取得単価
- 売却数量
- 含み益・含み損
- 年内確定損益
- ユーザーが入力した損失繰越
- 設定された税ルールと適用日
- NISA枠に関するユーザー入力情報

含み益のある銘柄を売る場合は、今税金を実現する推定影響をHOLDとの比較に含める。

NISAは基本の実現税影響を0として扱える設定を持つが、NISA内損失や枠の機会費用は別パラメータとして扱う。

税ルールは有効日付きでバージョン管理し、恒久的にハードコードしない。

## 13. Daily Portfolio Decision Engine

詳細は `docs/DAILY_PORTFOLIO_DECISION_ENGINE.md` を正本とする。

中心比較:

```text
代替ポートフォリオの期待効用
− 現在ポートフォリオをHOLDした期待効用
− 増分売買コスト
− 増分推定税影響
```

わずかな差では売買しない。

ノートレード帯を設け、現在の保有を維持する選択を正当に評価する。

単純なA→Bの1対1交換だけではなく、ポートフォリオ全体を同時最適化する。

## 14. 100株単位

初期実装は100株単位とする。

連続比率を単純四捨五入してはいけない。

```text
連続値で候補配分を計算
↓
100株単位へ離散化
↓
現金・銘柄上限・業種上限を再検査
↓
株数の組み合わせを再最適化
```

単元未満株は将来の別モードとする。

## 15. 機械学習の範囲

残すモデル候補:

- ルールスコア
- Momentum
- Ridge
- Elastic Net
- Logistic Regression
- LightGBM Regression / Ranker
- XGBoost Regression / Ranker
- CatBoost Regression / Ranker
- Quantile models
- 1日 / 5日 / 20日モデル
- 前場Meta-model
- 市場環境Soft Gating
- OOF Stacking
- MLP
- 1D-CNN / TCN
- GRU
- 小型Transformer
- TDnet構造化特徴

高度なモデルはChallengerであり、単純モデルを安定して上回った場合だけ採用する。

## 16. 検証

バックテストは状態付きにする。

前日の実際の現金・保有株・未反映約定を翌日へ引き継ぐ。

毎日、次を比較する。

- 現在のままHOLD
- Decision Engineの提案
- 上位10銘柄等加重
- 週次リバランス
- コスト無視最適化
- 税無視最適化
- 前場更新なし
- 現在保有を考慮しない方式

主な評価:

- 税・コスト控除後リターン
- Replacement Gain
- Hold Regret
- Reduce Regret
- Sell Regret
- No-trade Value
- Turnover
- Decision Reversal Rate
- Target-share Error
- Cash Utilization
- Tax Drag
- Trading-cost Drag
- 最大ドローダウン
- リスク集中
- 期間・業種・銘柄依存

## 17. 自動化

自動化する範囲:

- データ取得
- 品質検査
- 候補抽出
- 前場データ取得
- 11:30入力凍結
- 予測
- Cost / Tax計算
- Decision Engine
- 100株提案
- レポート保存
- スマホ通知
- モデル再学習候補の作成
- 運用状態の監視

自動化しない範囲:

- 実注文
- 注文取消
- 注文変更
- モデルの無条件な本番昇格

## 18. スマホPWA

詳細な画面・操作・状態・受入条件は `docs/UI_SPEC.md` を正本とする。

スマホは計算本体ではなく、確認・入力・監視画面とする。

初期画面:

1. 今日の提案
2. 保有・推奨
3. 銘柄詳細
4. 検証
5. 運用状態
6. 口座・コスト・税設定

重要表示:

- 11:30時点か
- データ更新日時
- モデル版
- 現在株数
- 推奨株数
- Action
- HOLD比較
- コスト
- 税影響
- 不確実性
- 見送り理由
- 入力待ちの実約定

## 19. 実取引の反映

初期版:

- ユーザーが実際の約定株数と価格を入力
- 手数料・税・その他費用を必要に応じて補正
- 翌日の保有状態へ反映

将来:

- SBI等の取引履歴CSV取込
- 口座残高CSV取込
- 約定照合
- 取込差分レビュー

実注文APIは本プロジェクトの中核に含めない。

## 20. セキュリティ

- APIキーをGitへ保存しない
- ブラウザへ提供者キーを渡さない
- 秘密情報をログへ出さない
- `.env` はコミットしない
- 本番データ取得失敗時に偽データへ切り替えない
- 古い・欠損・矛盾データでは提案を停止する
- 提案にはデータ時点とモデル版を必ず表示する

## 21. 対象外

初期中核には含めない。

- 自動注文
- 信用取引
- 空売り
- レバレッジ
- 高頻度売買
- 自律的な戦略書き換え
- 利益が出るまでバックテストを調整すること
- 公開マルチユーザー投資助言サービス
- 税務申告書作成
- LLMだけによる直接売買判断

- 最大保有銘柄数: 10

- 1業種上限: 30%

- 現物買いのみ
- 100株単位

- 12:30を主な意思決定対象時刻
